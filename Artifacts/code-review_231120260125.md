### 3. Error Handling — FAIL → RESOLVED (PASS)
Original finding (previous `src/App.jsx:49-52`):
- `default: return second;` silently swallowed any unrecognized `operator` value.
- Division (`first / second`) had no divide-by-zero handling (`5/0` → `Infinity`, `0/0` → `NaN` rendered raw to the display).

**Fix verified** — commit `6817f6c` ("fix(calculator): handle divide-by-zero and unknown operator in calculate()"), current `src/App.jsx:40-57`:
```
case "/":
  if (second === 0) {
    return "Error";
  }
  return first / second;
default:
  throw new Error(`Unsupported operator: ${operator}`);
```
- Divide-by-zero: `second === 0` now short-circuits to the string `"Error"` before the division runs — covers both `5/0` and `0/0` (any `second === 0` case), eliminating the raw `Infinity`/`NaN` display regardless of `first`'s value. Confirmed by reading current source; matches reported manual verification that `2+3=5` and `6/2=3` remain unaffected (both go through the unchanged `"+"` and non-zero `"/"` paths).
- Unknown operator: `default` now throws `new Error(...)` instead of silently returning `second` — surfaces the invalid state instead of masking it. (Still practically unreachable given the UI only ever passes `"+"/"-"/"*"/"/"`, but now fails loudly/safely if that ever changes, rather than failing silently.)
- `npm run lint` and `npm run build` reported clean post-fix (per user verification); no further static issue found in the new lines.
- No new finding. **This area is now PASS**, no blocking issue remains.
